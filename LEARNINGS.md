# Learnings

Gotchas hit while building. Append; don't rewrite.

- **[harness] `claude -p` waits 3s for stdin** unless stdin is redirected; always give it a file (we pass the prompt that way, no argv length limits). `--append-system-prompt-file` exists though `--help` doesn't list it.
- **[harness] stream-json result** carries `structured_output` (with `--json-schema`), `is_error`, `api_error_status`, `total_cost_usd`; usage arrives as `rate_limit_event` with `status` (allowed / allowed_warning / rejected), `resetsAt`, per-window `unifiedWindows`.
- **[windows] wsl.exe** prints UTF-16LE for `-l -v`, and expands `$VAR` in its command line; use `--exec` and pass a script path. Git Bash rewrites `/mnt/...` args unless `MSYS_NO_PATHCONV=1`.
- **[windows] Git Bash `sh` isn't on PATH** for processes started from PowerShell; find it via `git.exe`'s install dir (`core.WindowsShell`).
- **[linux sandbox] remounting a bind read-only** fails with EPERM unless the source's locked flags (nosuid, nodev, noexec, atime) are kept; device-node binds must not get `nodev`.
- **[linux sandbox] WSL Ubuntu 22.04**: unprivileged user namespaces work, `slirp4netns` present, no `bwrap`, no passwordless sudo.
- **[tests] Windows** won't remove a temp dir with an open file; close journals in tests.
- **[editing] python heredoc replacements**: `\\n` inside a non-raw triple-quoted string became a real newline in Go source; use the Edit tool for strings with escapes.
- **[windows] O_APPEND output handles** are append-only on Windows; MSYS `sh` exits 1 silently when writing to one. Give children a write handle seeked to the end (`proc.OpenOutput`).
- **[linux sandbox] unprivileged bind of a tree with submounts needs MS_REC** (else EINVAL: it could reveal what submounts cover). Then remount each submount read-only from /proc/self/mountinfo. WSL's /usr has /usr/lib/wsl/* submounts.
- **[go] exec.Command(name)** resolves `name` against the *current* process's PATH at construction and keeps the error; setting `cmd.Path` later doesn't clear it. Resolve against the target environment first.
- **[network] the local router's DNS doesn't resolve example.com** here; tests use github.com.
- **[wsl] Claude Code in WSL** lives in ~/.local/bin (not on non-login PATH), version 2.1.71 here; its help doesn't list `--append-system-prompt-file`, so inside sandboxes the prompt is passed inline.
- **[go] exec.Cmd.Start can only be called once**, even after it failed ("exec: already started"); a retry with different flags needs a fresh Cmd. Bit us when Windows (GitHub Actions job objects) refuses CREATE_BREAKAWAY_FROM_JOB.
- **[editing] Git Bash heredocs collapse a doubled backslash to one** even with a quoted delimiter here, so Python edits fed through them lose escapes; write the script to a file with the Write tool, or use Edit.
- **[landing] the box that lands this repo has no Go**, so a local `tests/green.sh` or cc-green run there checks nothing (cc-green ran 0 checks). The evidence that the suite passed is GitHub CI on the PR's head, which runs the same vet, short tests and e2e.
- **[go] `core.Clip` flattens whitespace** (it joins `strings.Fields`), so it is for one-line summaries; a diff or a log clipped with it loses its newlines. Slice the string instead.
- **[proc] a zombie answers kill(pid, 0) and keeps its start time**, so a turn orphaned by a Hive restart and never reaped (a container whose PID 1 doesn't reap) read as alive forever: "running turn 1 $0.00". Liveness also checks the process isn't a zombie.
- **[update] a release workflow runs the old release's updater, not main's**, so a fix shows up only from the release after it. v0.1.2's `hive update` asked the configured forge for the latest release, and install-smoke's local forge has none, so it printed `hive: not found`; main asks github.com over HTTPS. Under update.yml, from == to is skipped, so a release's own leg proves nothing until the next one.
- **[linux] `os.Executable` follows a rename**: it reads /proc/self/exe, so after an update moves the running binary to `hive.old`, it names `hive.old`. v0.1.1 restarted on that and came back as v0.1.1, so ubuntu from v0.1.1 never reaches the new version. `onDisk` (since v0.1.2) strips the suffix.
- **[update] old releases only follow the latest release**: v0.1.2 asks `gh release view` and v0.1.3+ GitHub's `/releases/latest`, and neither takes a tag, so a pre-release can't be reached by their updater. update.yml hands a pre-release over by hand (swap the binary, keep the old daemon.json, `daemon --detach --wait-for`). `release: published` fires for a pre-release too; `released` fires when it becomes a full release.
- **[ci] job logs need a login, annotations don't** (`/repos/<r>/check-runs/<job>/annotations`), so ci writes each `--- FAIL` and its next lines as an `::error::` annotation.
- **[daemon] `ResetSandbox` makes the next state poll probe the sandbox again** (bwrap, or several `wsl.exe` calls on Windows) while every other poll waits on its lock. Call it only when the sandbox setting changes; calling it on every saved setting made the Settings view slow.
- **[tui] PowerShell's `[Windows.Forms.Clipboard]::GetImage()` reads nothing outside an STA thread**, and pwsh defaults to MTA, so the clipboard read passes `-STA`. Over SSH nothing can reach the person's clipboard: no terminal sends an image, and a dropped file's path names a file on the other machine.
- **[windows] renaming onto a file another handle has open fails** ("Access is denied"): Go opens files without FILE_SHARE_DELETE, so a reader in the same daemon blocks `WriteFileAtomic`'s rename. It retries for two seconds on Windows.
- **[windows] a killed process's children live on** and keep their files open, so a test's TempDir can't be removed while a check's `sleep` or a detached turn still runs. The e2e puts each daemon in a job object that its cleanup ends (`contain_windows_test.go`).
- **[ci] a race that only Windows hits is usually a slow step widening a window**: reproduce on Linux by sleeping in the slow step (Extract, a measurement) rather than guessing. `TestCheckpointsBankEachGain`'s "banked 3" and `TestRiskPaths`'s tribunal-for-a-ceiling both came that way.
- **[windows] the wall clock ticks every ~15ms**, so a job that runs inside one tick has `Last == before`: `TestReportSharing` waited on `Last.After(before)` for a minute. Wait for a value to change, not for a time after the test's clock.
- **[modules] `git clone` makes its folder before it checks out**, so a module cloned in place was listed (and its empty Release read) before its files were there. Install clones under a hidden `.<name>-<id>`, checks it out and records it there, and renames it in whole.
- **[core] a message and a turn's end can cross**: `Send` checks the run takes messages, then queues; `endTurn` reads the run, then records the end. A warden's answer landing between them left a worker blocked with the answer unread (`TestBlockedWorkComesBack` on Windows). Both sides now wake a blocked run with a message waiting, each reading the run after its own write (`Runs.wake`). Reproduced on Linux with a sleep after `endTurn` reads the run and `FAKE:wardenslow`.
- **[modules] a folder in .hive/modules is a module as soon as it exists**: `List` reads the folder, so a clone in progress showed up with no release, granted to `*`. Install clones under a dot name (`.<name>-<id>`, which List skips) and moves it in only once its source record is written.
- **[windows] to replace a folder, rename the old one aside, then rename the new one in**: `RemoveAll` then `Rename` leaves it half deleted when a reader holds a file in it, with nothing put back. `kb.SeedSelf` stages beside the folder inside the knowledge base (one filesystem), retries each rename as `WriteFileAtomic` does, puts the old copy back if the new one won't go in, and journals `kb.self_failed`.
- **[core] a login can only be renewed in the harness's own window** (`renewWithin` in tokens.go). Claude Code 2.1.310 refreshes when `now + 300000 >= expiresAt` (`rC` in its bundle: five minutes), so a call earlier exits 0 and leaves the expiry where it was, which the Hive counts as a failure: widening the window raises false alerts. Codex 0.153.4 refreshes on a 401 ("Reloading auth", "No more recovery steps available"), so its window is 0. Nor is there a cheap earlier probe of the refresh token: `claude auth status` reads only local state and exits 0 while logged in, so a revoked refresh token shows only when a renewal is tried. Recheck both with `strings` on a new harness before changing the windows.
- **[harness] Claude Code's `total_cost_usd` is the session's running total, and `--resume` carries it on**: summing it per turn counted the lead's one long session as $7,282 when it had spent $58.89. A turn's spend is the rise since the last result line in the same session (`core.SessionSpend`); it matches the CLI's own `model_usage_since_last_result` to the cent. `--max-budget-usd` is not: it counts only what this process spent (the CLI's check is `totalCostUSD - restoredCostUSD`, 2.1.310), so a resumed turn's budget is what the run has left, with nothing added back.
- **[work] the queue reads merge=union itself, not with git** (`unionRules` in queue.go): last matching line wins, `**` spans directories, `-merge`/`!merge`/another driver clear union. It reads only the clone's root `.gitattributes` and skips `[attr]` macros, quoted patterns and nested `.gitattributes`; using any of those for a union doc means the queue still treats it as a conflict (it holds a brief back, never lets one through wrongly). Areas are cached per task against the brief text and that file's size and mtime.
- **[gate] a unix socket's path must fit in 108 bytes, and a gate side's TMPDIR is deep** (`<workspace>/.hive/gates/<project>/recursive/<run>/<side>/tmp`): `TestMeter` bound its socket under `t.TempDir()` and failed in every gate run whose `MkdirTemp` digits made the path 108 bytes or more, so `internal/gate` failed on both sides (or only one, by chance) and six gate runs in a row on 2026-10-24 kept nothing. A test that listens on a unix socket makes its dir with `os.MkdirTemp(shortTmp(), ...)`. To see which package failed in a gate run from before #422, look for which `ok  <pkg>` lines are missing from the side's `gocache` (Go caches only passing test results). Since #477 a side's TMPDIR is `<run>/t-<6 hex>` (and its suite's `<run>/e-<6 hex>`), the same length for candidate and control, so such a trap fails both sides or neither, never just the candidate.
- **[core] two daemons on one workspace show as two seq counters interleaved in `events.jsonl`**: from 17:30Z to 20:51Z on 2026-10-24 two daemons shared the journal; when a hold lifted at 18:53:07 both launched every due run, so runs got two `run.turn_started` for the same turn (two sessions editing one checkout). The daemon lock (#449) stops that. In one daemon, `Runs.launch` also refuses a run already running, one whose turn moved past the copy it was given, and one with a launch already in flight, and `Tick` steps the run as it is when claimed, not as listed. To check for it, look for a `seq` that doesn't rise.
- **[tui] a Windows console has no bracketed paste, and Windows Terminal keeps ctrl+v** (bubbletea v1.3.10, `readConInputs`): bubbletea reads the console with ReadConsoleInput and, after enabling VT input in `initInput`, `prepareConsole` sets the mode from 0 and drops it again, so a paste arrives as one key per character and a line break as Enter. `burst.go` joins keys that come under 25ms apart (3 or more, not one key repeating) into one paste. Windows Terminal (WSL and SSH sessions run in it too) handles ctrl+v itself and sends nothing when the clipboard holds only an image, so the image key there is alt+v, as in Claude Code. Its `powershell` read used to fail silently; `toolFailed` says why now. A burst also has to average under 3ms a key (`burstPace`): a console read hands a paste over microseconds apart, while fast typing with key rollover can land three keys inside 25ms but milliseconds apart, and "ok" plus Enter must send, not add a line. **Untested outside fakes** (as of 2026-10-25): no one has yet pasted text, a multi-line paste, a file drop or alt+v with a screenshot in a real Windows Terminal, nor timed whether a long paste's reads come more than 25ms apart (if so, raise `burstGap`).
- **[core] `go` in a fresh HOME leaves a detached telemetry child behind**: with no `upload.token` under `$XDG_CONFIG_HOME/go/telemetry/local`, every `go` command takes the daily token and starts a daemonized `** telemetry **` child that can outlive it, still writing into that home. The prefetch's temp home is under `.hive/cache`, so `RemoveTree` raced it ("directory not empty", #514). There is no env switch; `prefetch` writes `off` to `$XDG_CONFIG_HOME/go/telemetry/mode` (`TestPrefetchTurnsTelemetryOff`).
- A git that dies (out of memory) leaves its `.lock` behind and every later call in that repo fails with 'File exists'. `core.GitEnvT` removes a lock inside the repo's own `.git` once it is 20 minutes old (past any Hive git timeout) and retries once (#440).
- **[work] a waiting draft's next look is in memory only** (`m.later`): a look that finds the PR still a draft writes nothing, so after a restart every waiting draft is looked at once, one `GetPR` each, and then every 3 minutes again. `DraftSince` is in the task (it starts the 24h notice to the lead) and is cleared whenever the task is saved outside merging. A PR made a draft between `MergePR`'s own look and `gh pr merge` comes back from gh as "Pull Request is still a draft", which `MergePR` maps to `core.ErrDraft` (`draftRefused`), so it waits instead of counting a failure.
- **[core] go's telemetry mode file is read from `os.UserConfigDir`, which honours `XDG_CONFIG_HOME` on Linux only**: on macOS that is `$HOME/Library/Application Support`, on Windows `%AppData%`. A mode file written under `.config` is never read there, so telemetry stays on and its detached child races the removal of a throwaway home. `core.goTelemetryOff` writes it where the OS looks.
- **[remote] `hive remote` is tested only against a fake ssh** (`internal/api/remote_test.go` runs the test binary as ssh), as of 2026-10-25: never yet against a real sshd, a daemon restart over it, or an ssh session that drops. Its Knowledge pane shows no keys, since the knowledge base is a folder on the Hive's machine and the local one is an empty cache.
- **[core] a worker falls back only to a proven pick** (`Runs.proven`, from `run.finish` done on a run whose every turn was on that pick): a new test that sends a worker to a fallback model has to record a finish there first (`proven(c, model)` in `route_test.go`), or the worker waits for its own model's reset and the test goes red.
- **[e2e] killing a daemon's process group misses its module programs and turns**: `proc.Group` gives each module program a group of its own and turns start in sessions of their own, so a test that kills its daemon as a crash (`TestControlCenterFollowsARestart`'s `h.kill`) leaves the kb's `go run ./dream/...` running under `.hive/modules`, and t.TempDir's removal fails with "directory not empty" (#664). The cleanup's `settle` kills, via a `/proc` sweep (Linux), every process whose cwd, executable, open file, command line or environment names the test's folder (`TestStraysEnded`).
