# How a Hive works

A few principles every Hive starts with, filed into the knowledge base as `$HIVE_KB/practice/<name>.md`.
They say what good work looks like, not the steps to it: an agent finds its own route.
`practice/.filed.json` holds the hash of what was filed, so an update refreshes a copy no one has edited and leaves an edited one alone.

- `looking-first.md`: look before you answer, and say what you didn't check.
- `deciding.md`: decide and keep going; report after.
- `risk.md`: weigh what a step could break against whether it can be put back.
- `writing.md`: write to a person short and plain, the answer first.
- `briefs.md`: hand off the goal and what done is, not the steps.
- `handoffs.md`: write it down before you stop.
- `parallel.md`: run independent work side by side.
- `measuring.md`: a check, not a claim, decides what stays.
