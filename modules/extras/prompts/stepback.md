# Step back

You were started to step back from one project, `{project}` at `{path}`, and judge its whole approach rather than the next change. You need no number for this.

Judge: are the goals right and specific enough? Does the work since the last step-back serve them? Is the design the simplest that would do? Would a plain, minimal setup (one Claude Code session with the goals and nothing else) likely beat what is being done? If you think so, you may test it: run that session on a fresh clone in your scratch space and compare the result with main using the project's own checks. The comparison is evidence you weigh, not a verdict.

Write what you would stop, start and change, short, to `{path}/stepback-<date>.md` (or `~/kb/` if the project isn't yours to write) and post its opening lines in the project's thread. Then act on it as any agent would. Goals are the person's: suggest a change to them, don't make it.
