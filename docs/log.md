# Decision log

## 2026-10-22 Go, one static binary
- Decision: Go 1.27, single binary for CLI, daemon, sandbox launcher and in-sandbox agent client | Why: no runtime to ship, one-line install, cross-compiles | Tradeoff: no first-party Claude Agent SDK in Go; drive `claude -p --output-format stream-json` instead.

## 2026-10-22 Agents run as Claude Code print-mode sessions, resumed per turn
- Decision: each agent is a session id; a turn is one `claude -p --resume`; messages queue until the turn ends | Why: survives daemon restarts (output to files, processes detached, reattach by pid + start time); no long-lived pipes | Tradeoff: messages reach a busy agent at turn end (or via `hive agent inbox`).

## 2026-10-22 In-house Linux sandbox instead of bwrap
- Decision: namespaces built by the hive binary; egress through a host proxy that refuses local/private addresses | Why: no root, no packages (WSL Ubuntu had no bwrap, no sudo), and "no way to local services" needs filtering a plain shared netns can't give | Tradeoff: more code in `internal/sandbox`; macOS uses Seatbelt (untested).

## 2026-10-22 bubblewrap where Ubuntu restricts user namespaces
- Decision: when `kernel.apparmor_restrict_unprivileged_userns=1` (stock Ubuntu 23.10+), `sandbox-exec` hands the same mounts, tools and egress socket to `bwrap`, which runs `hive sandbox-inner` (loopback forwarder + command); WSL and other hosts keep the build's own namespaces | Why: the kernel refuses the hive binary's own user namespaces there, and bwrap's AppArmor profile is allowed them, so agents would otherwise fall back to bare runs | Tradeoff: two launch paths; `HIVE_SANDBOX_BWRAP=1` forces bwrap for tests.

## 2026-10-22 Commits leave checkouts as bundles made inside the sandbox
- Decision: `git bundle` runs sandboxed; host fetches with fsck, verifies descent from the recorded base | Why: an agent controls its `.git` (gitfile redirects, hooks, fsmonitor); host git never runs there | Tradeoff: an extra sandboxed step per landing.

## 2026-10-22 Checks use main's project.json; score/goals/settings are protected
- Decision: test/score commands come from main, not the PR; changes to `.hive/project.json`, `.hive/goals.md` and declared `protected` paths need the person | Why: a change must not rewrite the check it's judged by | Tradeoff: bootstrapping a project's score needs one person approval.

## 2026-10-22 Warden and tribunal run approved steps in the daemon
- Decision: replaces the v1 relay. Tiers route a step (T1 worker, T2 warden, T3 tribunal, ceiling person; autonomy moves T2); an approved script runs as `sh -c` in `.hive/risk/<id>` in the daemon after a sha256 digest check and `core.CeilingGuard`; the tribunal is three read-only runs over `tribunal_models`, two rounds, majority | Why: spec milestone 6, ported from the box's Claude build of the same spec | Tradeoff: no per-step sandbox beyond sh, its own directory and a timeout; the warden's script is the only thing weighed, so the warden must keep it to exactly the step.

## 2026-10-22 Read-only turns answer in structured output and read their run dir
- Decision: panelists vote through `--json-schema` like the reviewer; read-only turns get `--add-dir` for `/hive/run` and nothing else; a reviewer's land counts only with the token from its brief.md; the warden's brief gives host paths | Why: a real run found panelists had no shell to vote, reviewers couldn't read their inputs yet voted land, and warden scripts used sandbox paths on the host | Tradeoff: the fake harness now refuses shell and unlisted dirs on read-only turns, so it fails where Claude would.

## 2026-10-22 Squash merges, best-kept comparison
- Decision: squash merge pinned with `--match-head-commit`; measure each merge sha; compare with best kept score; revert via host-made commit + lessons line | Why: one commit per change makes reverts exact; best-kept stops drift under tolerance | Tradeoff: per-commit history of a branch isn't kept on main.

## 2026-10-22 Small = docs only
- Decision: no reviewer for docs-only changes ≤40 lines without protected paths; everything else is read | Why: comment-only detection in code is unreliable; conservative is safe | Tradeoff: a code typo fix still gets a review.

## 2026-10-22 System prompt inline inside sandboxes, file outside
- Decision: sandboxed turns pass `--append-system-prompt <text>`; bare Windows turns pass a file | Why: Windows argv is capped at 32k; inside the sandbox argv goes via the spec file with Linux limits, and older Claude Code builds may lack the -file flag | Tradeoff: two code paths in the Claude adapter.

## 2026-10-22 A full lead compacts; it keeps a journal instead of rotating
- Decision: no lead rotation. Each turn records the session's context size (the last reply's input plus cache tokens) on the run, shown in the control center; a lead keeps its journal in `$HIVE_BOX/notes.md`, and a lead that replaces one in a chat starts with that journal | Why: Claude Code 2.1.308 auto-compacts under `-p --resume` (a `compact_boundary` with `trigger: auto` in stream-json; the session went on and still recalled what it was told), so a lead neither dies nor errors at the limit | Tradeoff: compaction's summary is generic and comes late, near the window; the journal is what the lead chooses to keep.

## 2026-10-22 Agents install their own runtimes
- Decision: python, uv, node and go go into `.hive/tools` through `hive agent install`, with no root and no one asked; the person is told after. Agents see the folder read-only on PATH; the install runs in its own sandbox that may write it | Why: the owner's first live run sat blocked on a warden request for python, and he asked that the Hive install such things itself | Tradeoff: one version of each tool for every agent; a root install still goes to the person.

## 2026-10-22 The Hive's own code is a fork made on first need
- Decision: the self project is the person's GitHub fork of `release_repo`, created by `create_project --self`; a kept merge releases on the fork numbered on from the running version, the updater takes the newest of fork and upstream, and the fork's main is offered upstream as one PR once the person says yes, since it goes out in their name | Why: a release binary has no checkout and no write access upstream, and every change still goes through the sandboxed worker, checks, review and merge | Tradeoff: a new fork has Actions off until the person turns them on, so its releases carry no binaries before that.

## 2026-10-22 The source travels in the binary
- Decision: `go:embed` of the repository; the KB rewrites `kb/hive/` at each start | Why: the lead could not say how scores or schedules work from prompts alone; reading the source at the running version needs no network | Tradeoff: a bigger binary.

## 2026-10-22 Red tests on a red main wait instead of going back
- Decision: when a change's tests fail, the gate looks at main's own test result first; if main is red too, the change waits (no fix round spent) and main's failure is one alert per main commit; once main is green the branch is brought up to date and tested again, and only a failure then goes back to the worker | Why: workers were sent to fix main's environment, which they can't | Tradeoff: a change that adds its own failure on top of a red main isn't caught until main is green.

## 2026-10-22 Egress lists, the person's floor, seats that name their harness
- Decision: `egress.default` and `egress.roles.<role>` hold a run's proxy to listed hosts (plus its harness's API host; no list is every public host, as before), refusals journalled as `run.egress_refused`; `floor` in the config raises any step whose text touches an entry to the person, at routing and at the point of effect; `tribunal_models` entries may be `{harness, model}`, refused at save and at convene when the harness is missing; a vote counts only as one clean structured answer, and seats run isolated | Why: carry the lines an existing warden holds (a host allow list, a rules floor its classifier can't lower, seats across vendors, one-verdict parsing) so moving onto this core doesn't weaken them | Tradeoff: the floor is the same best-effort text match as the ceiling; on macOS each command gets its own proxy port.

## 2026-10-23 The score is fixed before the candidate
- Decision: a `./` file in the score command and the score's `paths` are protected like the settings, and each measurement carries the score's version (a hash of the command and those files at the measured commit); a merge whose version differs from the best kept one starts a new baseline instead of being kept or reverted against it, and a step-back seeds from and scores only under the version of the best | Why: the score runs from the checkout it measures, so a change to the score could pass as a gain, or a new scoring method be compared with old numbers (outside review, 10-23) | Tradeoff: the tests a score runs aren't covered unless listed in `paths`; a record from before versions is given the version of its own commit.

## 2026-10-23 An approved script's pin covers its text, not what it calls
- Decision: the digest stays on the script's text; the docs say so, and the warden and tribunal prompts ask for lines from agent-writable files inline or a fetch pinned by checksum | Why: an outside review found a script that calls a file the worker can still edit isn't frozen, and which files a shell script will read can't be worked out from its text, so a snapshot would be a guess | Tradeoff: the weighers carry this, not a check at the point of effect.

## 2026-10-23 An offline Hive says why and picks up again
- Decision: an error a turn ends with is read for a reachability cause (`core.Unreachable`: no internet connection, a failed connection, an expired login); the run parks with that line as its reason (`run.turn_ended.offline`), retries within 5 minutes at most, the lead's chat hears it once per outage, and the control center shows it above the dashboard until a turn gets through. A forge error of the same kind never counts toward a task giving up. A failed turn's reason reads `.wsl` as well as `.err`, and WSL gets the long name of any 8.3 short path | Why: on 10-23 an offline Windows Hive left chats unanswered with no word why, and was taken for a broken release | Tradeoff: the causes are read from the error's text, so a wording a harness changes falls back to the old "harness error; retrying".

## 2026-10-23 Projects list the files their score reads
- Decision: the setup brief, the README and the lead's guidance say to list every file the score reads in its `paths`, and a score set or changed with an empty `paths` raises a `score-paths` alert (at the start and when the score's version changes) | Why: the `./` guess misses a script the score calls, a test or a data file, which a candidate could still change (perms' read of the fixed-evaluator change) | Tradeoff: a warning, not a refusal, since only the project knows what its score reads.

## 2026-10-23 A scored worker's gains merge as it makes them
- Decision: on a scored project, a running worker's commit that beats the best kept score is tested, read and merged as a checkpoint while the worker keeps going; anything that would send it back just leaves it unmerged; the lead may brief one worker per distinct approach on an open-ended scored goal | Why: in a 35-minute run one worker committed a 5.8x gain twice but never finished, so main stayed at 1.0x, and it never tried the idea that reached 11.5x | Tradeoff: each new worker commit costs an extract and a score run; a checkpoint later reverted can make the worker's next commits conflict, which goes back to the worker like any conflict. A checkpoint's reviewer is told it reads unfinished work; a left-open checkpoint ends checkpoints for that task, so the person isn't asked again for each later commit.

## 2026-10-23 What opens under a row stays on screen
- Decision: a pane scrolls to keep the selected row and what opens under it in view (a setting's pick-list, the selected ask down to its options), the row first when both can't fit; settings' values wrap under their column, and wrapped text breaks words longer than the line | Why: the person's case, a pick-list under the bottom row clipped in a short window (docs/tui-text.md) | Tradeoff: summary rows still clip with `…`, since their detail opens.

## 2026-10-23 The Hive's own repo guards its root paths by default
- Decision: self projects always class the sandbox, the risk module, setup and the installers as root, and the gate's credential code, harness logins, release/daemon and the warden/tribunal prompts as high, joined in `Classify` from the binary (docs/root-paths.md) | Why: the Hive's project.json named no classes, so the code that acts outside the box got one read and released unasked | Tradeoff: more changes to the Hive need two reads, and root ones wait for the person at release.
- Decision: `.github/` is root and go.mod/go.sum high; Classify reads paths with `core.quotePath=false` and `-z`; every project protects `docs/REVIEW.md` | Why: perms' read of #153 (a quoted `é.go` slipped past the guard; release.yml builds every install's binary) and the owner's intent could otherwise change as a small docs merge | Tradeoff: a REVIEW.md edit now waits for an approval in every project.

## 2026-10-24 A local service opens to agents per port, on the person's grant
- Decision: `egress.local` lists loopback `host:port` grants (`hive egress grant|revoke`); the proxy dials a granted literal address past any list, Linux sandboxes relay it from the same address inside, Seatbelt allows the port; refusals are recorded with a reason (`unlisted` or `local`) and journalled with a line saying how a local one opens; `egress grant` / `egress.local` are ceiling words, so an agent's ask always reaches the person | Why: a refused 127.0.0.1 kept an agent from testing its own feature against a local Ollama, and the record said only the host (issue #124) | Tradeoff: a grant is for every run and check, not per role or project; loopback only, so a service on the LAN still can't open this way.

## 2026-10-24 Sharing has three levels
- Decision: a project is shared, private or isolated (docs/sharing.md); private is covered from every other run and walled from reach both ways like isolated, while its own runs mount the shared Hive like a shared project's | Why: the person listed "sharing-has-three-levels" with no detail, and the spec offers only the two ends; a one-way wall keeps a project's work out of sight without cutting its agents off from the Hive's records | Tradeoff: the middle level is a reading, not the person's words, and is listed as an open question; it reuses the isolated cover paths (`kb/isolated/`), so names still say "isolated" where they mean hidden

## 2026-10-24 A release is the latest only once ci and update pass on it
- Decision: the Hive cuts each release as a pre-release and the release module (`Publish`, every 10 minutes) makes it the latest once the `ci` and `update` workflows its release event started pass on its commit; update.yml hands a pre-release over the way an update does (binary swapped in place, `hive daemon --detach --wait-for <old pid>` reading the old daemon's daemon.json, so a v0.1.2 hive-v0 is renamed), since old releases only update to the latest, and runs the full by-itself update again on `released`; install-smoke runs on `released`, as the installer brings the latest | Why: v0.1.4-v0.1.6 published with update and ci red; update.yml looked for daemon.json in `.hive` after v0.1.4 moved it to `.hive/private` | Tradeoff: an old release's own download-and-restart is tested only after publishing; while Windows ci is red no release publishes.

## 2026-10-24 A merge waits for the forge's checks, and a read is of a diff
- Decision: the gate asks the forge for its checks on the exact head before merging (GitHub check runs, commit statuses, and suites with no runs listed yet as pending); running holds, failed goes back as a red test, can't start (startup failure, cancelled, stale, waiting on an action, queued over an hour) waits as the environment's and raises `main-red` once. `Effects.Merge` refuses too. A reviewer's verdict is bound to the diff its run was given (`DiffID`), and every read (the Hive's own, and outside ones the person records with `hive read`) holds for any head with the same own diff and no other; the old "a host-made update carries its reviewed sha's verdict" rule is gone. A PR that changes a path on main's `tests/LANDING-security.toml` is held until a perms or architect read is recorded as land on its diff (by paths alone; perms' FIX on #175 dropped the phrase match on the worker's account); the list's `required_checks` must each succeed on the head (none, neutral or skipped holds); the own diff is taken `--binary --full-index` so different binary blobs never share a read; main is merged into a PR only when the forge says it conflicts or wants it up to date, otherwise it merges as it is at the head that was read (autobox: each catch-up moved the head past the read) | Why: autobox: #143 merged while its CI still ran; #114 merged with conflict-resolution token logic perms never read; #148 and #149 changed listed paths (runs.go, internal/harness) and merged with no security read; #149 got eight reviewer runs, one per catch-up, each on the same diff | Tradeoff: context lines count in the own diff, so a main change right next to the change's lines asks for a new read too; a clean PR merges onto a main the Hive didn't test it with; outside reads arrive only by the person's hand (`hive read`), not from PR comments.
